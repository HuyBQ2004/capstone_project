# Integration Test Case — Security & Access Control (MF10 Feedback & Announcement Management)

---

## Feature: Ownership, RBAC, Tenant Isolation, Visibility, XSS, Logging & Upload Security

### 1. General Information

| Field | Value |
|---|---|
| Feature | Ownership, RBAC, Tenant Isolation, Visibility, XSS, Logging & Upload Security |
| Test requirement | This module carries the heaviest security load of the 13 modules — it touches children's health data (BR-142/BR-145) and announcement is the platform's largest XSS surface (thousands of parent recipients). Verify: Parents can only touch their own child's feedback (IDOR, C2, BR-007); the 7-role RBAC matrix (§16) is enforced on every endpoint; `schoolId` is read only from the JWT, never from query/body; DRAFT announcements and mis-targeted audiences never leak outside School Administration; `revisions[]` is School-Administration-only; announcement `content`/`title`/`revisionNote` are sanitized against XSS; notification `link` only accepts internal paths; unauthenticated calls are rejected and feedback content never reaches the logs; and attachment uploads go through `StorageService` with real content (magic-byte) validation. |
| Number of TCs | 10 |
