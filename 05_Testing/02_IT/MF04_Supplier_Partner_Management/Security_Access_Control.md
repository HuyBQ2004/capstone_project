# Integration Test Case — Security & Access Control (MF04 Supplier & Partner Management)

---

## Feature: Tenant Isolation, RBAC, Mass Assignment, Upload Safety, PII Logging, Auth, Rate Limiting, School Isolation, OpenAPI Contract

### 1. General Information

| Field | Value |
|---|---|
| Feature | Tenant Isolation, RBAC, Mass Assignment, Upload Safety, PII Logging, Auth, Rate Limiting, School Isolation, OpenAPI Contract |
| Test requirement | MF04 carries the module's #1 risk per `review_fix_plan.md` line 278: `partnerId` is the isolation key between competing suppliers — a single missed predicate leaks one supplier's compliance documents (business-sensitive) and delivery-staff national IDs (PII) to a competitor. Verify: a supplier cannot read or write another supplier's documents/delivery persons/applications/partnerships, and cross-tenant access resolves to `404 SUP-404` rather than `403` (M04-D10 — a `403` would confirm the record's existence to an attacker); the 7-role RBAC matrix (§16) is enforced on approve/reject/suspend/reinstate; `partnerId` sent in the request body/query is always ignored in favor of the JWT; file uploads are content-validated by magic bytes, not extension; CCCD and biometric data never leak into logs or event payloads; every endpoint requires a valid JWT except the 2 public registration endpoints; public registration is rate-limited and does not leak which accounts already exist; a School Administrator cannot approve an application filed with a different school; and the generated OpenAPI contract (gated behind D8) never exposes a UUID or an unmapped enum value. |
| Number of TCs | 9 |
