# Integration Test Case — Cross-Cutting Contracts: Client-Supplied ID, Pagination, Public ID, Error Envelope, Derived Columns (MF04 Supplier & Partner Management)

## Feature: Client-Supplied `id`, Pagination Contract, Public-ID Contract, Error Envelope, No Derived Columns

### 1. General Information

| Field | Value |
|---|---|
| Feature | Client-Supplied `id`, Pagination Contract, Public-ID Contract, Error Envelope, No Derived Columns |
| Test requirement | Verify the 5 module-wide contracts shared with the other 12 modules under `00_Common_Conventions.md`, as they apply to MF04's 5 list resources (`partners`, `supplier-documents`, `delivery-persons`, `partnership-applications`, `supplier-partnerships`): (1) a client-supplied `id` is honored as the record's `code`, with a duplicate rejected as `409 SUP-139` — **not** `SUP-409`, which carries a distinct business meaning (D5/L6, M04-D06); (2) every list endpoint returns the standard 5-field `PagedResponse` shape, clamps page/pageSize, and returns `200` (not `404`) on an empty result set (Team Plan §2b); (3) no UUID is ever exposed as `id`/`*Id` — path params and JSON foreign keys use the business code (D1/L1); (4) every error response has the 3-key envelope with `details` always an array, and `message` matches `error_message.md` byte-for-byte (D2/D7/L5); (5) no compliance-status column is physically stored anywhere in the schema (ADR-M04-4/ADR-M02-2). |
| Number of TCs | 5 |
