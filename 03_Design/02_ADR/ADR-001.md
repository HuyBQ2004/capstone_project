## Context — Bối cảnh

Hệ thống **School Food Safety Management Support System (SFMS)** cần phục vụ đồng thời nhiều loại người dùng (System Admin, School Admin, Medical Staff, Teacher, Parent, Supplier, Service Caterers) qua cả **Web browser** và **Mobile app**. Hệ thống có các yêu cầu kỹ thuật phức tạp:

**Ràng buộc kỹ thuật:**
- Xác thực sinh trắc học khuôn mặt (BR-051) yêu cầu **Face Recognition Service** tích hợp bên ngoài.
- GPS tracking bắt buộc khi nhận hàng và lưu mẫu (BR-073, BR-108) — cần Mobile native access.
- AI menu recommendation qua Gemini AI (BR-156) và RAG pipeline cần vector database riêng.
- Toàn bộ conversation với AI phải được archive bất biến (BR-157, BR-162).
- Thông báo push real-time (Firebase FCM) kết hợp email fallback (BR-159).
- Sao lưu tự động hàng tuần, mã hóa AES-256, off-site storage (BR-160, BR-161).

**Ràng buộc hạ tầng:**
- Triển khai trên một **Ubuntu Server 22.04 LTS** vật lý (điều kiện dự án sinh viên).
- Cần reverse proxy và DDoS protection để bảo vệ endpoint public.
- Yêu cầu CI/CD pipeline tích hợp SAST + SCA để đảm bảo code quality và bảo mật.

**Ràng buộc pháp lý:**
- Tuân thủ **PDPD (Nghị định Bảo vệ Dữ liệu Cá nhân Việt Nam)** — không thu thập sinh trắc học trẻ em (BR-173).
- Audit trail bất biến cho toàn bộ hành động (BR-162, BR-170).
- Mã hóa thông tin xác thực dịch vụ bên ngoài (BR-164).

## Options Considered — Các lựa chọn đã xem xét

| Option | Mô tả | Pros | Cons |
|--------|-------|------|------|
| **A** | **Monolithic** — Toàn bộ hệ thống trong một Spring Boot application, deploy trực tiếp trên VPS | Đơn giản, dễ debug, không cần orchestration | Khó scale từng thành phần, không tách biệt concern AI/Face/GPS; khó CI/CD riêng biệt |
| **B** | **Microservices thuần** — Tách từng domain thành service riêng (Auth, Menu, Inspection, Notification…) với Kubernetes | Scale tốt, fault isolation cao | Quá phức tạp cho team 5 người, chi phí infra cao, single Ubuntu server không hợp lý |
| **C** ✅ | **Modular Monolith + Docker Compose + Cloudflare Tunnel** — Spring Boot modular backend + Next.js web + Flutter mobile, orchestration bằng Docker Compose, Cloudflare làm reverse proxy + tunnel | Phù hợp quy mô dự án, isolation tốt qua Docker network, dễ CI/CD, Cloudflare miễn phí DDoS + TLS, dễ thêm service AI/Face sau | Network phức tạp hơn pure monolith; cần quản lý Docker volumes cho data persistence |
| **D** | **Serverless (Cloud Functions)** — Deploy logic lên AWS Lambda / Firebase Functions | Không cần quản lý server, scale tự động | Cold-start latency không phù hợp real-time inspection; chi phí unpredictable; phức tạp với stateful GPS/biometric data |

---

## Decision — Quyết định

**Chúng ta chọn Option C**: Kiến trúc **Modular Monolith với Docker Compose** và **Cloudflare Tunnel** làm ingress, cụ thể:

### Lớp Client
- **Web**: **Next.js** + TypeScript + Tailwind CSS + shadcn/ui (chạy tại `HTTP:3000`)
- **Mobile**: **Flutter** (iOS & Android — GPS, camera, push notification native)

### Lớp Edge / Proxy
- **Cloudflare** làm reverse proxy public (`sfsm.io.vn`, HTTPS 443, DDoS protection, TLS termination)
- **Cloudflare Tunnel** (QUIC / HTTP/2) kết nối Cloudflare ↔ Ubuntu Server mà không cần mở port public
- **Nginx** làm internal reverse proxy trong Docker network (HTTP:80, HTTP:8080) routing đến backend

### Lớp Backend
- **Spring Boot** REST API (HTTP:8000 — main API server)
- **Spring Boot** AI Service (HTTP:8001 — RAG pipeline, Gemini AI integration)
- **Spring Data JPA** làm ORM layer

### Lớp Dữ liệu (Internal Docker Network)
- **PostgreSQL** (JDBC - TCP 5432) — SQL database chính + pgvector cho vector embeddings (RAG)
- **Redis** (RESP - TCP 6379) — Cache session, token, rate-limiting

### Lớp External Services
- **Gemini AI** — AI menu recommendation + food safety chat (BR-156)
- **Face Recognition Service** — Biometric verification cho delivery person (BR-051)
- **GPS Provider** — Location verification khi nhận hàng và lưu mẫu (BR-073)
- **Email Service (SMTP TLS 587)** — Notification, forgot password (BR-159)
- **Cloudflare R2** — Object storage cho images và files (evidence photos)

### Lớp CI/CD & Security
- **GitLab** (gitlab.com)[https://gitlab.com/manhnc2/su26_sep490_g8] — Code version control
- **Semgrep** — Static Application Security Testing (SAST)
- **Trivy** — Software Composition Analysis (SCA) — container và dependency scanning
- **OWASP Dependency-Check** — SCA bổ sung
- Build → Test → SAST/SCA → Docker Build → Deploy pipeline

---

## Rationale — Lý do

**Tại sao C tốt hơn các options khác trong context SFMS:**

1. **Docker Compose phù hợp single-server constraint**: Dự án chạy trên một Ubuntu 22.04 LTS duy nhất. Docker Compose cho phép isolate services (backend, db, cache, nginx) trong **Internal Docker Network**, không expose port trực tiếp — tăng bảo mật mà không cần Kubernetes overhead.

2. **Cloudflare Tunnel loại bỏ port exposure**: Không cần mở port 443 hay 80 trực tiếp trên server. Tunnel QUIC/HTTP2 từ Cloudflare → Ubuntu đảm bảo server không bị scan từ internet, phù hợp BR-004 (session security) và BR-164 (mã hóa credentials).

3. **Next.js + Flutter phân tách concerns**: Web (School Admin, Medical Staff) cần dashboard phức tạp → Next.js SSR. Mobile (Teacher, Parent, Service Caterers, Delivery Person) cần camera + GPS native → Flutter. Hai platform phục vụ đúng use case.

4. **PostgreSQL + pgvector một database**: Tích hợp vector store vào PostgreSQL (pgvector extension) thay vì Pinecone/Weaviate riêng biệt — giảm external dependencies, đủ cho RAG pipeline của Gemini AI (BR-156, BR-157).

5. **Spring Boot modular** cho phép tách AI service (port 8001) khỏi main API (port 8000) — AI service có thể scale hoặc restart độc lập mà không ảnh hưởng core business logic.

6. **SAST + SCA trong CI pipeline**: Semgrep + Trivy + OWASP DC đảm bảo mọi pull request đều được quét bảo mật trước khi merge — phù hợp yêu cầu audit trail và compliance (BR-162, BR-164, BR-173).

## Consequences — Hệ quả

**Positive:**
- Isolation tốt giữa các service thông qua Docker network — một service crash không kéo theo toàn bộ hệ thống.
- Cloudflare miễn phí cho dự án giáo dục: DDoS protection + TLS + CDN — zero cost cho TLS certificates.
- PostgreSQL + pgvector hợp nhất relational data và vector embeddings — đơn giản hóa backup strategy (BR-160).
- Redis cache giảm tải database cho session token lookup (BR-004 timeout check) và rate-limiting (BR-003).
- CI/CD pipeline tích hợp security scan tự động — phát hiện vulnerability sớm.
- Flutter single codebase cho cả iOS và Android giảm chi phí phát triển mobile.

**Negative (trade-offs accepted):**
- **Single point of failure tại OS level**: Một Ubuntu server duy nhất — nếu server down, toàn bộ hệ thống down. Chấp nhận vì đây là dự án học thuật, HA multi-server ngoài scope.
- **Docker Compose không phải production-grade orchestration**: Thiếu auto-healing, rolling update phức tạp hơn Kubernetes. Chấp nhận vì quy mô dự án.
- **Cloudflare Tunnel dependency**: Nếu Cloudflare có sự cố, tunnel không hoạt động. Giảm nhẹ bằng fallback DNS configuration.
- **pgvector trên PostgreSQL**: Performance RAG queries có thể thấp hơn dedicated vector DB khi dataset lớn. Chấp nhận cho scale dự án hiện tại.
- **Spring Boot khởi động chậm**: JVM warm-up time ~15-30s — không phù hợp serverless nhưng acceptable cho persistent Docker container.

**Risks:**
- **R1**: Ubuntu server bị down, không có DR plan → Giảm nhẹ: weekly backup tự động BR-160 + documented restore procedure.
- **R2**: Cloudflare API quota / rate limit gây timeout → Monitor qua Cloudflare dashboard.
- **R3**: Face Recognition Service (external) có SLA thấp → Implement fallback: manual override bởi Service Caterers (ghi log đặc biệt).
- **R4**: Gemini AI cost vượt budget → Rate limiting ở AI Service layer (port 8001), cấu hình quota tại BR-163.
- **R5**: Docker volume data loss nếu không backup đúng → Automated weekly backup PostgreSQL + Redis snapshot (BR-160, BR-161).

**Compliance Impact:**
- `BR-001` — Password hash BCrypt: Spring Security default, không lưu plain text trong PostgreSQL.
- `BR-051, BR-060` — Face biometric: xử lý tại Face Recognition Service external, SFMS chỉ lưu reference ID — không lưu raw biometric trên server (tuân thủ PDPD / BR-173).
- `BR-157, BR-162` — AI conversation archive + Immutable audit log: PostgreSQL append-only table với trigger-based protection, không expose delete endpoint.
- `BR-160, BR-161` — Weekly backup AES-256: Automated cron job trong Docker, upload encrypted dump lên Cloudflare R2.
- `BR-163, BR-164` — External service credentials: Lưu trong Docker secrets / environment variables, không hardcode trong source code — Semgrep rule kiểm tra trong CI/CD.

**Decisions unlocked (ADR tiếp theo có thể viết):**
- `ADR-002`: Lựa chọn Authentication Strategy (JWT vs Session vs OAuth2) — liên quan BR-001 → BR-010
- `ADR-003`: Strategy cho Face Biometric Integration và PDPD Compliance — liên quan BR-051, BR-173
- `ADR-004`: RAG Pipeline Design cho Gemini AI Integration — liên quan BR-156, BR-157
- `ADR-005`: Database Schema Strategy cho Immutable Audit Trail — liên quan BR-162, BR-170
- `ADR-006`: CI/CD Pipeline Security Gates (SAST + SCA thresholds) — liên quan BR-164

```
Theo ADR-001 (SFMS Overall Architecture):

1. PHẢI deploy tất cả services (Spring Boot API, Spring Boot AI, PostgreSQL, Redis, Nginx) 
   trong cùng một Docker Compose file với network tên "sfms-internal". Không được expose 
   port của PostgreSQL (5432) hay Redis (6379) ra ngoài Docker network.

2. KHÔNG được lưu credentials của external services (Gemini API key, Face Recognition 
   API key, GPS Provider key, SMTP password, Cloudflare token) dưới dạng hardcode trong 
   source code. PHẢI dùng Docker secrets hoặc environment variables từ .env file 
   (không commit .env vào git — Semgrep rule đã enforce).

3. Tất cả request từ internet PHẢI đi qua Cloudflare Tunnel → Nginx (HTTP:80/8080) 
   → Spring Boot (HTTP:8000/8001). Không được cấu hình port-forwarding trực tiếp từ 
   internet đến Spring Boot container.

4. Identity (userId, role, schoolId) của mọi request PHẢI được extract từ JWT token 
   do Spring Boot API (port 8000) phát hành — không tin tưởng userId từ request body 
   hay query parameter.

5. Layer Spring Boot AI Service (port 8001) chịu trách nhiệm TOÀN BỘ giao tiếp với 
   Gemini AI API. Spring Boot main API (port 8000) KHÔNG được gọi trực tiếp Gemini API — 
   phải đi qua internal HTTP call đến port 8001.

6. Mọi file ảnh và file upload (evidence photos, compliance documents, batch certificates) 
   PHẢI được lưu lên Cloudflare R2, KHÔNG lưu trong Docker volume của server. 
   Server chỉ lưu đường dẫn R2 trong PostgreSQL.

7. Face biometric raw data KHÔNG được lưu trong PostgreSQL của SFMS. SFMS chỉ lưu 
   face_reference_id (UUID) trả về từ Face Recognition Service. 
   (Tuân thủ BR-173 — PDPD, không thu thập biometric trẻ em.)
```
