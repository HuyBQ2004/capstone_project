## Context — Bối cảnh

**ADR-001** định nghĩa kiến trúc **Production** với đầy đủ: Cloudflare Tunnel, Nginx, Redis, AI Service, Face Recognition Service, GPS Provider, SMTP, Cloudflare R2, CI/CD SAST/SCA, Ubuntu Server 22.04 LTS.

Tuy nhiên, môi trường **Local Development** của từng thành viên trong team không cần và không nên chạy toàn bộ stack đó vì:

- External services (Face Recognition, Gemini AI, GPS, SMTP) yêu cầu credentials và có chi phí hoặc quota giới hạn.
- Cloudflare Tunnel và Nginx không cần thiết khi localhost đã accessible.
- Redis cache có thể bỏ qua — Spring Boot cấu hình để fallback về in-memory hoặc tắt cache.
- CI/CD pipeline chỉ chạy trên GitHub Actions, không phải máy local.

**Mục tiêu ADR-000**: Định nghĩa stack tối giản, đủ để dev/test toàn bộ business logic mà không cần infrastructure bên ngoài.

## Options Considered — Các lựa chọn đã xem xét

| Option | Mô tả | Pros | Cons |
|--------|-------|------|------|
| **A** | Chạy toàn bộ production stack (clone ADR-001) trên máy local | Giống production nhất | Nặng (~8 containers), cần credentials, chi phí API quota, Docker Desktop RAM > 8GB |
| **B** | Chỉ chạy backend Spring Boot bằng IDE (IntelliJ/VSCode), Next.js bằng `npm run dev`, PostgreSQL bằng Docker đơn lẻ | Nhẹ, khởi động nhanh, debugger dễ attach | Không có Docker network, mỗi dev cấu hình tay — dễ "works on my machine" |
| **C** ✅ | **Docker Compose rút gọn** — 3 service: `nextjs`, `spring-boot`, `postgres`. Flutter chạy trực tiếp trên máy (Android Emulator / iOS Simulator). Không có Redis, Nginx, AI Service, external services | Cân bằng: reproducible environment + nhẹ + không cần credentials; `docker compose up` là xong | Cần Docker Desktop; mock một số external service calls |

## Decision — Quyết định

**Chọn Option C**: Docker Compose rút gọn với 3 service cốt lõi + Flutter native.

> **Cập nhật 2026-07-28 (Nam chốt) — Version Pin Backend:** nâng từ Spring Boot 3 (Java 17+) lên
> **Spring Boot 4.1.x (Java 25 LTS)**. Lý do: framework mới nhất tại thời điểm dự án triển khai, hiệu năng
> JVM tốt hơn, hỗ trợ Virtual Threads tốt (phù hợp workload I/O-bound của SFMS: nhiều query DB + gọi
> external service), vòng đời hỗ trợ dài (LTS) nên giảm số lần phải nâng cấp lớn trong vòng đời dự án.
> Áp dụng đồng thời cho dev (ADR-000) và production (ADR-001) — không có gap version giữa 2 môi trường.
> Đã đồng bộ tại `07_implement/01_MVP_Backend_Implementation_Plan.md` §3 và
> `07_implement/00_Team_Work_Assignment_Plan.md` §2c-2 (ràng buộc stack trong prompt sinh TDS).

| External Service (Production) | Dev Replacement |
|-------------------------------|----------------|
| Gemini AI | Spring profile `dev`: trả về mock JSON response hardcoded |
| Face Recognition Service | Mock endpoint luôn trả `{ match: true, faceId: "mock-uuid" }` |

## Rationale — Lý do

1. **`docker compose up` one-command setup**: Mọi thành viên team chỉ cần Docker Desktop + clone repo → `docker compose -f docker-compose.dev.yml up -d` → dev ngay. Không cần cài PostgreSQL, Node.js, JDK thủ công.

2. **Spring Boot DevTools hot-reload**: Container mount source code qua volume → thay đổi Java file → auto-restart trong ~3 giây, không cần rebuild Docker image.

3. **Next.js HMR (Hot Module Replacement)**: Tương tự, thay đổi `.tsx` → browser tự refresh. Volume mount đảm bảo HMR hoạt động bên trong container.

4. **Flutter ngoài Docker**: Flutter cần access trực tiếp Android SDK / Xcode toolchain — không containerize được hợp lý. Chạy native và point đến `localhost:8080`.

5. **PostgreSQL persistent volume**: `./data/postgres` mount vào container — data không mất khi `docker compose restart`. Dev seed data một lần, dùng nhiều session.

6. **Tách biệt rõ ràng môi trường**: Dùng `application-dev.yml` trong Spring Boot (không commit secrets) và `.env.local` trong Next.js. Không có rủi ro nhầm lẫn production credentials.
   > **Cập nhật 2026-07-31 (Nam, lúc dựng MF01 backend):** thực tế Spring Boot dùng file **`.env`** ở root `Backend/` (nạp qua thư viện `spring-dotenv`, đọc vào `application.yml` qua `${VAR:default}`) thay vì một file `application-dev.yml` riêng — đơn giản hơn (một profile `application.yml` duy nhất, không phải maintain 2 file), và đồng bộ quy ước `.env`/`.env.example` với phần Next.js ở mục này. `application-dev.yml` **không được tạo** trong repo thật. Xem `.env.example` tại `04_Development/Backend/`.

## Consequences — Hệ quả

**Positive:**
- Onboarding thành viên mới < 15 phút: `git clone` → `docker compose up`.
- Không tốn quota API của external services khi dev/test.
- PostgreSQL exposed ra host (`:5432`) cho phép dùng GUI client (DBeaver, TablePlus) để kiểm tra data.
- Flutter có thể test camera và GPS qua emulator mà không cần thiết bị thật.
- Tốn ít RAM hơn: ~1.5GB RAM so với ~4GB nếu chạy full production stack.

**Negative (trade-offs accepted):**
- **Gap với production**: Không có Redis → một số race condition liên quan cache không được phát hiện ở local. Giảm nhẹ: integration test chạy trên CI với Redis.
- **Mock external services**: Behaviour của Face Recognition mock khác với service thật. Giảm nhẹ: staging environment (nếu có) chạy real service.
- **Không có Nginx**: Next.js gọi trực tiếp Spring Boot → một số CORS, header, proxy path issue có thể xuất hiện khi deploy. Giảm nhẹ: Nginx config được test trong CI deploy step.
- **Spring Boot DevTools không dùng trong production**: Phải đảm bảo `devtools` dependency scope là `developmentOnly` trong `build.gradle`.

**Risks:**
- **R1**: Developer commit `.env.local` (frontend) hoặc `.env` (backend) chứa credentials → Giảm nhẹ: `.gitignore` bắt buộc (`.env`, `.env.*`, trừ `!.env.example`) + Semgrep rule trong pre-commit hook.
- **R2**: Data trong `./data/postgres` volume chứa PII test data bị lộ nếu chia sẻ máy → Giảm nhẹ: chỉ dùng fake/anonymized test data trong dev.
- **R3**: Port conflict (`:3000`, `:8080`, `:5432`) với service khác trên máy dev → Document rõ, cho phép override qua `.env`.

**Compliance Impact:**
- `BR-001` — BCrypt password hash **PHẢI** được áp dụng ngay từ dev profile — không được dùng plain text password trong database dù là môi trường test.
- `BR-006` — Password policy validation logic phải hoạt động đầy đủ trong dev — không được tắt validation để tiện test.

**Decisions unlocked:**
- `ADR-003`: Authentication Strategy (JWT configuration cho cả dev và prod)
- `ADR-005`: Database Migration Strategy (Flyway/Liquibase — shared schema giữa dev và prod)

### `docker-compose.dev.yml` (tham khảo)

```yaml
version: '3.9'

services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: sfms_dev
      POSTGRES_USER: sfms
      POSTGRES_PASSWORD: ${DB_PASSWORD:-sfms_dev_pass}
    ports:
      - "5432:5432"
    volumes:
      - ./data/postgres:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U sfms"]
      interval: 10s
      timeout: 5s
      retries: 5

  spring-boot:
    build:
      context: ./backend
      dockerfile: Dockerfile.dev
    environment:
      SPRING_PROFILES_ACTIVE: dev
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/sfms_dev
      SPRING_DATASOURCE_USERNAME: sfms
      SPRING_DATASOURCE_PASSWORD: ${DB_PASSWORD:-sfms_dev_pass}
    ports:
      - "8080:8080"
    volumes:
      - ./backend/src:/app/src    # hot-reload source mount
    depends_on:
      postgres:
        condition: service_healthy

  next-app:
    build:
      context: ./frontend
      dockerfile: Dockerfile.dev
    environment:
      NEXT_PUBLIC_API_URL: http://localhost:8080
    ports:
      - "3000:3000"
    volumes:
      - ./frontend:/app
      - /app/node_modules          # anonymous volume để không override node_modules
    depends_on:
      - spring-boot

networks:
  default:
    name: sfms-dev-network
```

## §AI Prompt Constraint ⭐ CASE 2.0 — BẮT BUỘC

```
Theo ADR-000 (SFMS Local Development Environment):

1. PHẢI dùng file `.env` (nạp qua `spring-dotenv`, xem `.env.example`) cho secrets local —
   KHÔNG tạo `application-dev.yml` riêng (cập nhật 2026-07-31). Profile "prod" và "staging"
   KHÔNG được activate trên máy developer.

2. KHÔNG được hardcode connection string, password, hoặc API key trong source code.
   PHẢI đọc từ environment variables. File `.env` (backend) và `.env.local` (frontend)
   chứa secrets PHẢI có trong .gitignore; chỉ `.env.example` được commit.

3. BCrypt password hash (BR-001) và password policy validation (BR-006) PHẢI hoạt 
   động đầy đủ trong dev profile. KHÔNG được tắt security để tiện test.

4. Mock external services (Face Recognition, Gemini AI) PHẢI trả về response 
   đúng format contract (same JSON schema) như production service — chỉ khác data.
   Điều này đảm bảo integration test không cần thay đổi khi switch sang real service.

5. Flutter app kết nối đến backend qua:
   - Android Emulator: http://10.0.2.2:8080/api
   - iOS Simulator:    http://localhost:8080/api  
   - Physical device:  http://<LAN-IP-của-máy-dev>:8080/api
   KHÔNG được dùng IP cứng trong source code — phải đọc từ app_config.dart.

6. Database dev (sfms_dev) PHẢI dùng test data anonymized — không copy production data
   vào môi trường local dưới bất kỳ hình thức nào (tuân thủ PDPD / BR-173).
```
